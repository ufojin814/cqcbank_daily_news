# 重庆地区城商行理财产品对比分析项目

> 面向重庆银行总行个人部财富管理平台，对重庆地区主要城商行代销理财产品进行系统性对比分析。

## 项目简介

本项目以理财数据源为核心，对重庆地区 10 家目标银行（重庆银行、重庆农村商业银行、重庆三峡银行、重庆富民银行、成都银行、汉口银行、厦门银行、哈尔滨银行、广东南粤银行、大连银行）代销的理财产品进行整理、匹配与对标，输出产品总表和三张分类分表；双供应商周再对 A（普益标准）、B（联信智评·深度查询）两份最终报告做逐只差异与覆盖对照。

当前默认方案为**方案四**：全量表 + 重庆银行在售清单匹配 + 三张分表。A、B 两条管线严格隔离，互不读取对方产物、互不回填归属；对比工作簿在两份最终报告齐备后生成。

## 快速开始

### 1. 环境依赖

```bash
pip install pandas openpyxl xlrd numpy
```

- Python 3.9 ~ 3.11（实测 3.11.9）
- pandas、openpyxl、xlrd、numpy

### 2. 数据源准备

每次分析需要：

- **A 供应商全量表**（普益标准）：2 个 Excel（如 `银行理财产品查询.xlsx`、`银行理财产品查询 (1).xlsx`），`header=1` 读取。
- **B 供应商全量表**（联信智评·深度查询）：7 个 `深度查询YYYYMMDDHHMMSS.xlsx`，`sheet_name='深度查询'`、`header=7` 读取；同目录上一期 7 表与 `ADMIN_SM_ROLE_*.xlsx` 不得并入。
- **重庆银行在售清单**：如 `代销理财当前在售清单（2026.11.13）.xlsx`，`header=1`，前 8 列按位置重命名。
- **清单必须留存**：微信接收文件在 `RWTemp` 临时目录会被清理，执行前复制到 `data/`。
- **业绩基准字段名每期变化**，执行前用命令确认并写入 `BENCH_COL`：

```bash
python -c "import pandas as pd; df=pd.read_excel(r'C:\Users\Administrator\Downloads\银行理财产品查询.xlsx', header=1, nrows=1); print([c for c in df.columns if '业绩比较基准' in str(c)])"
```

### 3. 执行分析

单供应商周（A）：

```bash
# 第一步：修改 match_cqb.py 的 DATA1 / DATA2 / NEW_LIST
python scripts/match_cqb.py

# 第二步：修改 run_plan2.py 的 DATA1 / DATA2 / BENCH_COL
python scripts/run_plan2.py
```

双供应商周：先跑 A 管线（只读 A 两表 + 清单），再跑 B 管线（只读 B 7 表 + 清单），两侧产物验收通过后再跑对比脚本生成 A/B 对比工作簿。A、B 之间不得互相读取产物或回填归属。

`scripts/_cqb_matched.pkl` 由脚本自动定位到同目录，无需手工配置。该文件与运行环境的 pandas/numpy 版本绑定，必须在同一环境内先跑匹配脚本再跑主脚本，不要跨环境拷贝 pkl。

### 4. 输出产物

- **三张分表（A/B 各一版）**：`reports/重庆地区代销理财对比_[A/B供应商_]YYYYMMDD_HHMM.xlsx`
  - Sheet1 重庆银行产品（按在售清单匹配，保留全部份额）
  - Sheet2 重庆本土银行产品（三峡银行、重庆农商行、富民银行，排除重庆银行）
  - Sheet3 其他城商行代销产品（成都、汉口、厦门、哈尔滨、南粤、大连，排除重庆银行）
- **产品总表（A/B 各一版）**：`reports/重庆地区城商行理财_产品总表_[A/B供应商_]YYYYMMDD_HHMM.xlsx`（全量字段）
- **B 侧清单/口径工作簿**：`reports/供应商数据质量对比_B供应商_YYYYMMDD_HHMM.xlsx`
- **A/B 对比工作簿**：`reports/供应商数据质量对比_A_B_YYYYMMDD_HHMM.xlsx`（清单逐只 / 覆盖对比 / 字段口径 / 结论与限制）

三张分表固定 8 列：代销机构、发行机构、产品名称、业绩基准中枢(%)、业绩基准下限(%)、近1年收益(%)、近1年回撤(%)、产品类型。B 侧无回撤字段，回撤列统一 `无`。

## 核心逻辑（方案四）

1. **重庆银行产品**：按用户在售清单，通过三级匹配（产品代码精确 → 标准化名称精确 → token 交叉）在全量表中查找，**不按全量表代销机构字段筛选**。
2. **表 2/表 3 候选池**：取“代销机构含任一目标银行”的完整行集，替换重庆银行前先留存，避免多机构代销行被整行剔除。
3. **份额口径**：以 `产品登记编码` 为产品级配对键；逐份额按代销机构展开；同一（产品, 银行）已有子份额则丢母份额；该产品所有子份额的 `代销机构` 字符串全同 → 视为产品级聚合、改用母份额 1 行；否则按对比逻辑收敛（达标子份额全留，未达标留 1 款）。
4. **业绩基准**：只取当次窗口字段 `业绩比较基准（...）`，单点值中枢=下限，区间值取中值/下限；挂钩类非数值文本原样展示。
5. **标红**：同 `运作子模式` 内，同业中枢且下限均高于重庆银行该类型“最高 2 只代表”的最高中枢/最高下限，整行标红；重庆银行行绿色。
6. **收益/回撤**：近 1 年 → 近 6 月 → 近 3 月 → 近 1 月顺位取值并标注来源；回撤保留 2 位小数。
7. **B 供应商降级口径**：无分级份额类型字段、无回撤字段；表 2/表 3 按 `(银行, 登记编码)` 产品级收敛留基准中枢最高 1 行，回撤统一 `无`；归属直接取自 B 自身 `代销机构`（空回退 `第三方代销机构`）；基准为当前快照，挂钩形式/说明保留原文不解析。
8. **A/B 对比**：两侧各自出表后再对照；命中状态分双命中/仅 A/仅 B/双未命中；名称去理财子前缀与份额后缀后比期号、期限、前缀；份额按登记编码归集字母集合；两侧同窗口收益才比较（阈值 0.05pct），跨窗口不直接比较；两侧挂钩型基准均不解析数值。

## 关键注意事项

- 业绩基准字段名随导出窗口变化，**每次都要改** `BENCH_COL`。
- 全量表存在产品名称为空的脏记录，读入与匹配结果都要 `dropna(subset=['产品名称'])`。
- 现金管理类产品不设固定业绩比较基准，字段为空属正常。
- 清单原件会随微信临时目录清理，必须复制到 `data/`。
- 输出前核对：表1 = 匹配到数量；表2 + 表3 = 主脚本“收敛后”行数；每个（银行, 产品）组至少 1 行。
